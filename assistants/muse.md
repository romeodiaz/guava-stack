# Meta Muse Bot adapter

- **Connect your hub:** tell Muse "Connect my Notion" (or the app your hub lives in, if Muse offers it) and approve access to your guava-hub. Start with just the hub, not your whole workspace.
- Muse doesn't let you upload your own skills, so don't install them as files. Keep the skills in the hub and have Muse read the matching one from there when a task needs it.
- **Add the standing instructions:** click the bot's avatar, open the Fingerprint tab, and open SOUL.md. Add these lines at the end, then save. Add to what's there; never replace or delete anything. Fill in the owner's hub. The routing line reads the models from Stack settings, so swapping one there needs no change here:
  ```
  Before any substantive task, load my guava-hub in Notion first (Context, Rules and Skills) and treat it as the source of truth.
  Model routing: use the head-chef and line-cook in my Stack settings, read fresh each task, through the CLI each one names at the effort it names (`claude -p --effort <effort>` for Claude Code, `codex exec -c model_reasoning_effort=<effort>` for Codex): the head-chef for orchestration, research, planning, brainstorming, copywriting, validation, review, verification, fuzzy and hard problems; the line-cook for bulk execution, coding, sub-agent tasks, worker threads and long-running jobs; quick replies and connector lookups stay with you; if either CLI fails, do the task yourself and say so; when a skill defines how it runs, follow the skill and use routing only for work it leaves open. Run routed work through the CLI without being asked, and mention which one you used.
  When I say "update guava-stack", "update guava-hub", "update guava-router" or "update founder-mode", follow the Update step in that piece's skill from github.com/romeodiaz/guava-stack: guava-hub/skills/guava-hub/SKILL.md (it also handles "update guava-stack"), guava-router/skills/guava-router/SKILL.md or founder-mode/skills/founder-mode/SKILL.md.
  When I ask to change my setup (for example "change my setup", "apply my Stack settings" or "check for newer models"), follow the Change your setup step in guava-hub/skills/guava-hub/SKILL.md from github.com/romeodiaz/guava-stack.
  ```
  Leave IDENTITY.md alone. Use MEMORY.md only for facts about the owner, never for passwords, keys or other secrets.
- **Verify:** start a new chat and ask "Write a short intro about my business." It passes if the intro uses details from the hub.
- **Run the CLI steps and model router in Muse's own terminal.** Muse can install Claude Code with npm and usually has Codex already; follow step 1 of the Model Router setup in guava-router (it checks and skips what's installed). For sign-in, the owner opens the link and signs in with their own account, then pastes any code straight into Muse, never anywhere else. When Muse asks to share information with anthropic.com or openai.com, choose Allow once, not Always allow.
- Muse asks before important actions like sending email. Keep those approvals on.
- A local Markdown or Obsidian hub doesn't work with Muse, since it can't reach a folder on the owner's computer. Owners who want one use the Claude desktop app's Code tab instead (see `guava-hub/skills/guava-hub/backends/local-markdown.md`).
