Guava Stack (guava-hub plugin): before substantive work in this session, load the owner's guava-hub through whichever connector holds it (Notion, Google Drive or Microsoft 365), or from the local Markdown or Obsidian folder the owner's instructions name: their Rules page (with a section for each rules skill listed under Rules in guava-stack settings), their Context page (which starts with guava-stack settings) and enabled skills. A rules skill marked for one kind of work, such as "(coding)", applies only to that work. Treat the hub as the source of truth.
- Notion hub: work from the local copy in `~/.guava-hub` instead of fetching pages from Notion. When it exists, its Context, Rules and skill list are in this start-up context; read a skill's file in `Skills/` only when a task needs it (a skill's attached files stay in Notion).
  - Refresh it when it's due (15 minutes old or more) or the owner asks: one Notion search with `page_url` set to the guava-hub ID in `sync.md`, query "guava-hub" and page_size 50 lists every hub page with its last-edited time. Fetch only Context, Rules and the skill pages edited at or after the `synced` minute in `sync.md`, plus new ones, delete files for pages that are gone, then set `synced` to now (`date -u +%Y-%m-%dT%H:%MZ`). If nothing changed, only `synced` changes.
  - No copy yet: load the hub from Notion, then save it. `Context.md` and `Rules.md` hold each page's text as plain Markdown, without images, columns or icons. Each skill goes in `Skills/<name>.md`, starting with `name`, `description` (on one line) and `notion` (its page ID) between `---` lines, then the skill's text. `sync.md` holds `synced: <time>`, then a `<page>: <ID>` line each for guava-hub, Context, Rules and Skills.
  - Change the hub in Notion, never only in the copy, then fetch the page you changed into the copy. The Change log page is for the owner: don't load it or copy it.
- Model routing: follow the head-chef and line-cook in guava-stack settings, re-reading those two lines from the hub right before each hand-off so a swap applies even mid-session, through the tool and at the effort each one names (in Claude Code, a Claude line-cook runs as a subagent on its model and effort). With a Notion hub, `find ~/.guava-hub/sync.md -mmin -15 | grep -q . && grep -E '^- (head-chef|line-cook):' ~/.guava-hub/Context.md` prints the two lines from the copy, or nothing when the copy is due for a refresh: refresh it, then read them. Each slot's effort is part of its setting: the same model at a different effort is still a hand-off. If the head-chef and line-cook match in model and effort, or guava-stack settings names none, do the work yourself with no hand-offs.
- Model check: if the head-chef is a Claude model and this session runs on a different one, tell the owner in one line and offer the fix: `/model <head-chef model ID>` for this session, and the same ID as `"model"` in `~/.claude/settings.json` for new local sessions (back it up first). Change nothing without a yes, and ask at most once per session.
- If the owner asks to change their setup ("change my setup", "apply my guava-stack settings", "check for newer models"), follow the Change your setup step in the guava-hub skill. If they say "update guava-stack", "update guava-hub", "update guava-router" or "update founder-mode", follow the Update step in that skill ("update guava-stack" is in guava-hub).
- If the hub can't be found or reached, say so once and carry on. A local hub can't be reached from a cloud session; say that in one line. A cloud session has no local copy, so it loads a Notion hub through the connector. If the owner has no hub yet, they can say "set me up".
