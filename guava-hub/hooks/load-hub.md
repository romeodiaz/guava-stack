Guava Stack (guava-hub plugin): before substantive work in this session, load the owner's guava-hub through whichever connector holds it (Notion, Google Drive or Microsoft 365), or from the local Markdown or Obsidian folder the owner's instructions name: their Rules page (with a section for each rules skill on the Rules line in guava-stack settings), their Context page (which starts with guava-stack settings) and enabled skills. A rules skill marked for one kind of work, such as "(coding)", applies only to that work. Treat the hub as the source of truth.
- Model routing: follow the head-chef and line-cook in guava-stack settings, re-reading those two lines from the hub right before each hand-off so a swap applies even mid-session, through the tool and at the effort each one names (in Claude Code, a Claude line-cook runs as a subagent on its model and effort). Each slot's effort is part of its setting: the same model at a different effort is still a hand-off. If the head-chef and line-cook match in model and effort, or guava-stack settings names none, do the work yourself with no hand-offs.
- Model check: if the head-chef is a Claude model and this session runs on a different one, tell the owner in one line and offer the fix: `/model <head-chef model ID>` for this session, and the same ID as `"model"` in `~/.claude/settings.json` for new local sessions (back it up first). Change nothing without a yes, and ask at most once per session.
- If the owner asks to change their setup ("change my setup", "apply my guava-stack settings", "check for newer models"), follow the Change your setup step in the guava-hub skill. If they say "update guava-stack", "update guava-hub", "update guava-router" or "update founder-mode", follow the Update step in that skill ("update guava-stack" is in guava-hub).
- If the hub can't be found or reached, say so once and carry on. A local hub can't be reached from a cloud session; say that in one line. If the owner has no hub yet, they can say "set me up".
