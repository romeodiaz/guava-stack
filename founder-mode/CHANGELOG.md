# Changelog

founder-mode version history.

- 2026-10-16 (setup only): Assistants check each guava-stack settings line when it changes. A head-chef or line-cook model gets one tiny test prompt on its own tool, and the hub, assistant, AI setup and Rules lines are matched against the choices setup offers. A typo gets one message with the closest match, such as "Did you mean Claude Opus 5.5?", and nothing changes without a yes. In a ChatGPT-only setup, Codex makes the fix itself, since there's no Claude to hand it to. In Codex and the ChatGPT desktop app, the plugins now show as guava-hub and guava-router, matching founder-mode. The founder-mode rules are unchanged from v2.1.0.
- v2.1.3 (2026-10-16, setup only): The hub's four Notion pages are named in lowercase: context, rules, skills and changelog (one word). The local copy's files follow suit (`context.md`, `rules.md`, `skills/`), and so do the Google Drive, OneDrive and local Markdown hubs. The founder-mode rules are unchanged from v2.1.0.
- 2026-10-16 (setup only): Every hub edit, not just a head-chef or line-cook swap, now reaches sessions that are already open within 15 minutes. At the start of each task, a session whose hub is 15 minutes old or more reloads the pages you edited (Context, Rules or skills) and follows the new version. The founder-mode rules are unchanged from v2.1.0.
- 2026-10-16 (setup only): The Skills database gets an 8-bit stack of books as its icon, and the README shows it with the Context and Rules icons. The README is shorter, with icons and emojis in place of long text. Setup no longer adds a model-routing skill, since guava-stack settings and the standing instructions already cover routing. Notion's connector can't set a database icon, so setup asks you to click Add icon, choose Link and paste the image's URL. The founder-mode rules are unchanged from v2.1.0.
- v2.1.2 (2026-10-16, setup only): The word Rules appears once in guava-stack settings, as the heading. Under it, each rules skill that's on gets its own line by name, such as `- founder-mode`, and in Notion the founder-mode image has no caption. The head-chef and line-cook lines each get a sub-bullet with the full list of their jobs, and their images lose their captions too. The founder-mode rules are unchanged from v2.1.0.
- 2026-10-16 (setup only): The Skills database in Notion gets the 📚 icon. The founder-mode rules are unchanged from v2.1.0.
- 2026-10-16 (setup only): With a Notion hub, Claude Code and the Code tab keep a local copy of the hub in `~/.guava-hub` and read that instead of calling Notion each time. Each new session gets your Context, Rules and skill list from it at start-up, reads a skill's full text only when a task needs it, and refreshes only the pages that changed once the copy is 15 minutes old, with one Notion search. A head-chef or line-cook swap reaches the computer at the next hand-off within 15 minutes, or right away if you say "refresh my hub". The change log now lives on its own Change log page, which assistants never load. Notion stays the source of truth, and Grok Bot, Muse, the chat apps and cloud sessions read it as before. The founder-mode rules are unchanged from v2.1.0.
- 2026-10-16 (setup only): A head-chef or line-cook swap in guava-stack settings now applies at the next hand-off, even in a session that's already open: assistants re-read those two lines right before each one. In Claude Code and the Code tab, a new session also checks its own model against the head-chef and, if they differ, offers the one-line fix and asks once. The Claude-only setup no longer uses `opusplan`: the Code tab runs on the head-chef and hands line-cook work to a subagent on the line-cook's model and effort, like every other setup. The founder-mode rules are unchanged from v2.1.0.
- 2026-10-16 (setup only): Guava's lines in `~/.codex/AGENTS.md` and `~/.claude/CLAUDE.md` now sit between `<!-- guava-stack:start -->` and `<!-- guava-stack:end -->`. Setup and updates back the file up, change only what's between the markers and ask you once for all the files, so a rename like the hub's no longer means editing by hand. The founder-mode rules are unchanged from v2.1.0.
- v2.1.1 (2026-10-16, setup only): Stack settings is now called guava-stack settings. It ends with two headings of its own, Rules and then head-chef and line-cook, each over its lines, so they're easy to find and swap. In Notion, the founder-mode 8-bit image sits under Rules and the head-chef and line-cook images sit side by side under theirs, each above its lines. If there's no Rules line yet, founder-mode adds the Rules heading and line. The founder-mode rules are unchanged from v2.1.0.
- v2.1.0 (2026-10-16): Rule 26 no longer uses Cisco Skill Scanner. Before installing a third-party skill, your assistant looks it up on skills.sh: if it's listed, it shows you the security audit results and won't install anything an audit flags. If it isn't listed, such as your own or a client's skill, your head-chef reads the whole skill and tells you in plain words what it makes the assistant do. Hub setup checks imported skills the same way. In Notion, the Skills database gets the 📖 icon, a recipe book for your skills. The two model slots are called head-chef and line-cook everywhere, lowercase with the dash, including the Stack settings lines (`head-chef:` and `line-cook:` instead of `Planner:` and `Builder:`) and the app routing instructions. The other 26 rules are unchanged from v2.0.6.
- v2.0.6 (2026-10-16): The hub is called guava-hub everywhere: the Notion page, the Google Drive, OneDrive and local folders (default `~/Documents/guava-hub`), the hub instruction lines and every setup step. The Agent Rules page is now just Rules, and in Notion it has the founder-mode 8-bit logo as its icon whichever rules skills you use, so founder-mode no longer adds a logo under How to work with me. The Rules page starts with a list of the rule sets on it, such as `founder-mode v2.0.6` or `Oct 15 import`, and rules you import during setup are saved word for word as one set named for the day. That list is the only place a version is written, so founder-mode no longer adds a version line under How to work with me. Profile & Context is now just Context. Rule 25 now says "the Rules page" instead of "Agent Rules"; the rest of the founder-mode rules are unchanged from v2.0.0.
- v2.0.5 (2026-10-16, setup only): Stack settings gets a Rules line listing every rules skill that's on, `Rules: founder-mode` by default. You can add more, for all work or one kind of work, such as `Rules: founder-mode, <coding rules> (coding), <design rules> (design)`. Each gets its own section in Agent Rules, and when two disagree your own Agent Rules come first, then the stricter one. Turning on founder-mode adds it to the line. Hub setup no longer writes rules of its own: Agent Rules holds only your own rules and the rules skills you turn on, so an owner without founder-mode keeps just their own. In Notion, the hub page is now called guava-hub, with the 8-bit brain as its icon, Profile & Context gets the guava logo and Agent Rules keeps the shield, and founder-mode puts its 8-bit logo under How to work with me; the Notion hub line is now "Load my guava-hub in Notion first." The founder-mode skill's title now carries its real version, which updates compare against. The founder-mode rules are unchanged from v2.0.0.
- v2.0.4 (2026-10-16, setup only): Effort is now set per slot. The same model can be head chef on High and line cook on Medium, and builder work still goes out at the builder's effort. Only the same model at the same effort in both slots skips the hand-offs. Claude Code commands now pass the effort too (`--effort`). The founder-mode rules are unchanged from v2.0.0.
- v2.0.3 (2026-10-16, setup only): Updates no longer carry steps for older setups: no clean-up of copies under old names (guava-mode, owner-mode-rules and others), no adding Stack settings to hubs set up before it existed, and no rewording of old routing lines. "update guava-stack" now compares your hub and saved instructions with this version's setup and offers to change what differs. Setup no longer asks "one model or two?": for one model that does everything, put the same model as head chef and line cook, and the router sets up only that model's tool. The README lists What you get first, and coming soon is in italics. The founder-mode rules are unchanged from v2.0.0.

The AI still reads the parts it needs through your own Claude or ChatGPT plan, so this is private, not offline; local models for the router are coming soon. The Cursor, Devin and other third-party tool rows marked coming soon are gone, the README no longer links the Grok Bot template or the pending marketplace listing (Grok Bot setup starts from the Start here line), and the Cursor plugin files are removed. founder-mode now finds the Agent Rules file in a local hub too. The founder-mode rules are unchanged from v2.0.0.

- v2.0.0 (2026-10-15): Rebuilt from a fresh read of five agent setups ([pstack](https://github.com/cursor/plugins/tree/main/pstack) with poteto-mode, [superpowers](https://github.com/obra/superpowers), [Matt Pocock's skills](https://github.com/mattpocock/skills) and [gstack](https://github.com/garrytan/gstack)) plus Paul Graham's [Founder Mode](https://paulgraham.com/foundermode.html) essay, translated for business owners. The plugin, its folder and the rules are now called founder-mode, and the skill is founder-mode-rules. 27 rules in five groups, led by three that never bend: ask before anything you can't take back ("sounds good" isn't a yes to send), check the real result (helpers' reports included), and say how you know things. New ideas include a checkable definition of done, pushing for specifics (interest isn't demand), finding out why before fixing, never lowering the bar, a fresh second check on anything customers or money touch, hand-offs that mark what was checked versus assumed, and (from Founder Mode) no black-box work, leading with bad news, and weighing the owner's own results over standard advice. Setup now saves the rules word for word, and a stricter Agent Rule wins.
