# Claude adapter

- **Claude desktop app, Code tab:** for owners who don't use Grok Bot or Muse. With both plans it routes to Codex through OpenAI's plugin; with Claude only it hands line-cook work to a subagent on the line-cook's model and effort. It's Claude Code with no terminal: Claude runs the installs and sign-ins itself, asking first. Set up in a Local session: the Codex plugin, the Codex CLI and the ChatGPT sign-in live on the owner's computer, and cloud sessions don't get plugins. Paste the Start here line, or add the `romeodiaz/guava-stack` marketplace (run `claude plugin marketplace add romeodiaz/guava-stack` as a shell command in the session, with a yes) and install **guava-hub**, **guava-router** and **founder-mode** from **+ > Plugins**.
- The Code tab runs on the owner's computer, so every hub and router setup step applies. The router's "Never skip the hub" step is optional.
- **From the phone:** with Remote Control on for new sessions (`"remoteControlAtStartup": true` in `~/.claude/settings.json`, or desktop Settings, then Claude Code, then **Connect new sessions to Remote Control**), the owner opens Code tab sessions from the Claude phone app while the computer is on and the app is open. When it's off, Claude chat on the phone still has the hub and the routing instruction, so set up App routing too.
- **Cloud sessions in the Code tab aren't supported:** they don't load the plugins, Codex or the owner's sign-ins. Tell the owner to pick **Local** when they start a session; there's no setting to make it the default.
- In the Code tab and Claude Code, installing the guava-hub plugin is enough: its start-up hook tells every new local session to load the hub and follow guava-stack settings, so nothing goes in `~/.claude/CLAUDE.md`. Without the plugin, add the standing instructions to `~/.claude/CLAUDE.md` between `<!-- guava-stack:start -->` and `<!-- guava-stack:end -->`, as **Local instruction files** in the guava-hub skill says. Claude chat (web, desktop and phone) has no start-up hook, so it still needs the hub instruction line.
- Claude is the head-chef here. Do head-chef work yourself. In the Claude-only setup, send line-cook jobs to a subagent on the line-cook's model and effort; with both plans, send them to Codex through OpenAI's [Codex plugin for Claude Code](https://github.com/openai/codex-plugin-cc), which the router setup installs.
- To import existing context, ask the owner to paste or export it. Don't read Claude memories or chat history yourself.
- **Updating:** "update guava-stack" (or one piece, such as "update founder-mode") runs the Update step in the guava-hub skill. Plugin updates need a Local session, and apply in the next new session.
- **Claude chat (web, desktop and phone):** connect the hub's connector (Notion by default), add the hub instruction line from the backend's file, such as "Load my guava-hub in Notion first.", and upload the skills from `guava-hub/skills/`, `guava-router/skills/` and `founder-mode/skills/` if the owner wants them there. Chat can't run CLIs, so set up the Model Router's **App routing** step instead: it adds instructions that tell Claude which model plans and which executes.
