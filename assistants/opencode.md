# OpenCode adapter: OpenCode desktop app and OpenCode CLI

- For owners with no Claude, ChatGPT or Google AI plan, who pay OpenRouter per use instead. OpenRouter works with every model company, so they get a tool that belongs to none of them: **OpenCode**, free and open source, with a desktop app for daily chat and a CLI (`opencode`) on the same computer for the skills that run programs. Both read the same settings in `~/.config/opencode`, so one Notion connection and one set of standing instructions cover them.
- **Get the app:** the owner installs OpenCode from https://opencode.ai/download. Then, before pasting anything, they connect OpenRouter themselves in the app: type `/connect`, pick **OpenRouter** and paste a key made at [openrouter.ai/settings/keys](https://openrouter.ai/settings/keys) with a credit limit they're comfortable with. The key stays in OpenCode's own sign-in file (`~/.local/share/opencode/auth.json`); never ask them to paste it into the chat. Add credits at [openrouter.ai/settings/credits](https://openrouter.ai/settings/credits) if the account has none. Then they pick a model with `/models` (the OpenRouter head-chef pick in guava-router's `models.yaml` is a good default), open a session in their home folder and paste the Start here line there. OpenCode's agent runs commands on the computer, so it does the installs below itself, with one yes per step.
- **Billed per use:** every message costs OpenRouter credits at the model's price. Say so once at the start, with the credit limit tip above.
- **No phone app yet:** OpenCode has none. Say so once at the start, instead of setup's line about the phone, and offer the two ways onto the phone in setup step 7.
- **Connect your hub** (setup step 1), checking first without asking (`opencode --version`, `opencode mcp list`) and skipping what's there:
  - Install the CLI, if `opencode` isn't there yet: `curl -fsSL https://opencode.ai/install | bash` on a Mac or Linux, or `npm i -g opencode-ai`.
  - Add Notion for both apps: `opencode mcp add notion --url https://mcp.notion.com/mcp`. It writes `~/.config/opencode/opencode.jsonc` (or the `opencode.json` already there), which the desktop app reads too.
  - Sign in: `opencode mcp auth notion` opens Notion's sign-in page in the owner's browser, where they approve the workspace they'll use for their guava-hub. `opencode mcp list` then shows Notion connected.
  - Back in the desktop app, start a new session so Notion's tools show up.
- **Add the standing instructions:** save the full list from setup step 2 at the end of `~/.config/opencode/AGENTS.md`, the global rules file the OpenCode desktop app and CLI both read, backed up first (see **Backups** in setup step 2). Add to what's there; never replace or delete anything. There's no length limit, so leave out only the model routing and session-check lines, as for a bot. If that file doesn't exist yet but `~/.claude/CLAUDE.md` does, OpenCode reads that one instead, and making the new file stops it: tell the owner, and ask whether to copy its lines across first. Changes apply in a new session.
- **Skills:** keep them in the hub and read the matching one from there when a task needs it. Also install Guava's skills as files, so updates and the skills that run programs work here: `npx skills add romeodiaz/guava-stack -g -y -a opencode` (it puts them in `~/.agents/skills`, which OpenCode reads). Without Node, skip this and read them from the hub.
- **Connect your computer** (setup step 6) is already done by the steps above. Just check it in a new terminal: `opencode run "What's in my guava-hub?"` passes if it answers from the hub.
- The Model Router and last30days-research come with adding Grok Bot or Muse (**Add a bot** in the setup skill). On the bot, the router runs the OpenRouter models through the Pi coding agent, signed in to the same OpenRouter account.
- **Workflow review:** make the report as an `.html` file in the owner's Downloads folder, never a shared link.
