# Pi adapter: Pi CLI, then the OpenCode desktop app, on OpenRouter

- For owners with no Claude, ChatGPT or Google AI plan, who pay OpenRouter per use instead. OpenRouter works with every model company, so they get tools that belong to none of them, both free and open source: the **Pi** coding agent (`pi`) on their computer, which signs in to OpenRouter in the browser and does setup, and the **OpenCode desktop app** for daily chat. Pi goes first, so the owner never makes or pastes an OpenRouter key: setup hands Pi's sign-in to OpenCode.
- **Before you start** (the owner does these in a terminal, the only part of setup that needs one):
  1. Install Pi: `curl -fsSL https://pi.dev/install.sh | sh` on a Mac or Linux, or `npm i -g @earendil-works/pi-coding-agent` on Windows.
  2. Run `pi`, type `/login openrouter`, choose **Sign in with OpenRouter**, and approve in the browser (making a free OpenRouter account if they have none). Add credits at [openrouter.ai/settings/credits](https://openrouter.ai/settings/credits) if the account has none, and set a credit limit on the key Pi made at [openrouter.ai/settings/keys](https://openrouter.ai/settings/keys).
  3. Pick a model with `/model` (the OpenRouter head-chef pick in guava-router's `models.yaml` is a good default), then paste the Start here line into Pi.
- **Billed per use:** every message costs OpenRouter credits at the model's price. Say so once at the start, with the credit limit tip above.
- **Connect your hub** (setup step 1), checking first without asking (`pi mcp list`) and skipping what's there: `pi mcp add notion --url https://mcp.notion.com/mcp`, then `pi mcp login notion`, which opens Notion's sign-in page in the owner's browser, where they approve the workspace they'll use for their guava-hub. `pi mcp list` then shows Notion connected. If Notion's tools don't show up in this session, have the owner quit Pi and run `pi -c`, which picks the same session up again, then say "carry on with setup".
- **Add the standing instructions:** save the full list from setup step 2 at the end of `~/.pi/agent/AGENTS.md`, the instructions file every Pi session reads, backed up first (see **Backups** in setup step 2). Add to what's there; never replace or delete anything. There's no length limit, so leave out only the model routing and session-check lines, as for a bot. Changes apply in a new session.
- **Skills:** keep them in the hub and read the matching one from there when a task needs it. Also install Guava's skills as files, so updates and the skills that run programs work here: `npx skills add romeodiaz/guava-stack -g -y -a pi opencode` (it puts them in `~/.agents/skills`, which Pi and OpenCode both read).
- **Connect your computer** (setup step 6): Pi already runs on the computer, so this step connects the **OpenCode desktop app** for daily chat. Have the owner install it from https://opencode.ai/download (just install it, no sign-in), then, with one yes for the plan:
  - **Hand over the OpenRouter sign-in**, without showing the key: back up `~/.local/share/opencode/auth.json` if it exists, then run

    ```
    pi auth print-api-key --provider openrouter | node -e 'const fs=require("fs"),path=require("path"),f=path.join(require("os").homedir(),".local/share/opencode/auth.json");const k=fs.readFileSync(0,"utf8").trim();if(!k)process.exit(1);let a={};try{a=JSON.parse(fs.readFileSync(f,"utf8"))}catch{}a.openrouter={type:"api",key:k};fs.mkdirSync(path.dirname(f),{recursive:true});fs.writeFileSync(f,JSON.stringify(a,null,2),{mode:0o600});fs.chmodSync(f,0o600);console.log("OpenRouter handed to OpenCode")'
    ```

    It reads Pi's key and writes it only into OpenCode's own sign-in file, keeping anything else there. Never print the key, put it in a message, the hub, a memory, a task or a prompt.
  - **Notion for OpenCode:** add `"notion": {"type": "remote", "url": "https://mcp.notion.com/mcp"}` under `mcp` in `~/.config/opencode/opencode.json` (or the `opencode.jsonc` already there), backed up first. With no file yet, create it as `{"$schema": "https://opencode.ai/config.json", "mcp": {"notion": {"type": "remote", "url": "https://mcp.notion.com/mcp"}}}`. OpenCode asks the owner to sign in to Notion the first time it uses it.
  - **Standing instructions for OpenCode:** the same full list at the end of `~/.config/opencode/AGENTS.md`, backed up first. If that file doesn't exist yet but `~/.claude/CLAUDE.md` does, OpenCode reads that one instead, and making the new file stops it: tell the owner, and ask whether to copy its lines across first.
  - **Check it:** the owner opens OpenCode, starts a session in their home folder, picks the same model with `/models` (OpenRouter's models are listed now), and asks "What's in my guava-hub?". It passes if it answers from the hub, after the owner approves Notion's sign-in page.
- From then on, the owner chats in OpenCode day to day, and Pi stays on the computer for the skills that run programs and anything the owner would rather do in a terminal. Both read and save to the same hub and Notion Memory.
- The Model Router and last30days-research come with adding Grok Bot or Muse (**Add a bot** in the setup skill), which is also the way to work from the phone. On the bot, the router runs Pi too, signed in to the same OpenRouter account. oracle-council finds Pi's OpenRouter sign-in already done.
- **Workflow review:** make the report as an `.html` file in the owner's Downloads folder, never a shared link.
